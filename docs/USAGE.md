# 使用 Recast

线上验收地址：[打开 Recast](https://recast-xvc.mixuechu.workers.dev)。在左侧填写项目维护者提供的访问码即可开始；线上上传音频无需本地隧道。以下启动步骤只用于本地开发。

## 启动

在项目目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的 Local 地址，默认是 `http://localhost:8787`。保持终端运行；关闭时按 Ctrl+C。若提示端口占用，先关闭之前启动的 Recast，再运行；也可执行 `npm run build` 后用 `npx wrangler dev --port 8788` 启动另一端口。

本机已配置模型与火山 ASR 密钥；从 GitHub 新克隆则需复制 `.dev.vars.example` 为 `.dev.vars` 并在本地填写。修改密钥后需要重启服务，单纯刷新网页不会重新读取密钥。

## 第一次体验：真实视频

1. 首页点击“试读一段真实课程”，或在视频链接中输入 `https://www.youtube.com/watch?v=nykOeWgQcHM`。
2. 可填写生成要求，例如：“面向编程初学者，按五个主题章节整理，解释术语，保留单人讲述，约1800字。”
3. 等待文章逐段出现。最后可能显示“正在核对原文引用”；只有结构和引用校验通过才标记完成。
4. 点击文章中的“原文”，查看对应的字幕片段；带时间轴的字幕可以点击时间跳回 YouTube。
5. 点击章节旁的“5W1H”。总结中每项可查看原文；原文未提到的信息显示“未明确提及”。

这个测试视频来自 MIT OCW。YouTube 获取受限时，会明确显示已使用同一视频的 MIT 官方字幕；官方字幕也不可访问时才使用注明日期的固定快照。页面不会把快照标成实时抓取。其他视频没有通用的官方字幕替代源，失败时请导入字幕。

## 整理自己的视频

- **视频链接**：输入公开视频链接。支持 watch、短链接、Shorts、embed 和 live 链接格式，但能否获得字幕取决于视频与 YouTube 访问情况。
- **粘贴字幕**：可以粘贴纯文本、SRT 或 VTT。纯文本可以生成文章与总结；逐段校对需要带时间轴的 SRT / VTT。
- **生成要求**：可以指定任务类型、风格、受众、篇幅和重点；请求与字幕不符的事实不会得到可靠支持。精确字数仍需要人工复核。

## 对照两份字幕

1. 文章生成后，点击“校对字幕”。文章中断但已经读取字幕时，也可校对原素材再生成。
2. 在“导入第二份字幕”中选择或粘贴另一份 SRT / VTT。两份应来自同一音频、相同语言，且时间轴起点一致。
3. 点击“比较字幕”。系统标记数字、否定表达和文字差异，不自动判断正确答案。
4. 针对分歧选择“保留原字幕”“采用候选”或“手动修订”。必要时点击“回听”。可以用批量按钮，但请先确认它符合你的判断。
5. 点击“保存校对”。所有分歧确认、且没有未保存修改后，才可点击“按校对结果生成新文章”。
6. 新文章使用独立记录。旧文章与旧总结仍保留在“最近整理”，不会被校对操作覆盖。

不同字幕切句方式可以不同，系统会按重叠的时间区间合并对应片段。若两份音频剪辑不同、整体时间偏移或语言不同，差异不能直接用于判断识别质量。

## 火山辅助识别

**当前线上已知限制：** 上传与回听可用，但火山无法下载本站workers.dev音频链接（45000006），因此“上传并开始识别”尚未通过线上验收。可以先导入第二份字幕完成校对，或使用经火山验证可下载的公网音频直链。后续接入媒体域名或对象存储后再解除此限制。

本地需要让火山读取上传的文件。先安装官方 `cloudflared` 客户端（本机已有），再用下面的命令代替普通启动：

```sh
npm run dev:asr
# 若旧服务占用了8787：PORT=8788 npm run dev:asr
```

它会自动建立临时音频回调；只有带随机令牌的音频 GET/HEAD 可以从外网访问，网页、模型接口和管理 API 仍只在本机访问。关闭终端会断开回调，重启后旧音频链接失效，需要重新上传。这个命令用于本地测试，不部署网站。线上使用同站 HTTPS 地址，无需本地隧道。

1. 打开“校对字幕”，展开“火山辅助识别”。
2. 选择“上传音频”，选取同一视频、同一起点的 MP3 / WAV / M4A / OGG / AAC（最多24 MB），点击“上传并开始识别”。也可切换“音频链接”，输入公网HTTPS直链并选择格式。
3. 上传文件临时保存1小时，通过随机下载链接供火山读取；删除文章会同时删除音频。识别可能产生费用。YouTube页面链接不能当作音频链接。
4. 可以关闭面板，稍后再回来查看；任务状态和结果保存在服务端。识别完成后自动显示两份字幕的差异。
5. 上传的音轨可直接在面板播放；点击差异片段的“回听”会定位到该时间。按上述步骤逐段确认，然后保存并生成新文章。
6. 查询失败时可点“重试查询”，继续查询同一个任务，不会重复提交一份识别任务。

YouTube音频自动提取、视频上传及转码不在本轮范围；当前通过上传对应音轨完成辅助识别。文件头与大小会在服务端检查。链接模式需要直接音频地址，不能依赖登录、Cookie或网页确认。GitHub raw和常见CDN可能本机能访问、服务商却无法下载。“停止等待”只停止本应用查询，不保证撤销服务商任务；可继续查询同一个任务。

真实 ASR 测试音频可以使用仓库中注明来源的 MIT 90 秒片段：`tests/fixtures/mit-lecture-90s.mp3`。它对应原视频 90–180 秒，测试时配套导入 `mit-lecture-90s.srt`；不要将这段音频直接拿来与整段 43 分钟字幕比较。

## 保存、恢复与错误处理

- 右上角复制或下载 Markdown；文章中的原文编号用于本应用溯源，导出后不包含完整字幕。
- “最近整理”用于恢复同一浏览器的记录。记录保存24小时，到期删除；不同浏览器、不同本地端口的最近列表不互通。
- 停止生成后保留已生成正文，未完整的文章不能生成章节总结。
- 模型断流会明确报错；不会把残缺文章标为成功。可以重试，或先校对素材再生成新文章。
- 重要内容需要自己核对原始音频，存在真实字幕编号不代表已经完成事实审计。
